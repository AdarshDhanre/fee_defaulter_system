Section 01
Project Kya Hai? (Overview)

Fee Defaulter System ek enterprise-grade web application hai jo educational institutions ke liye banaya gaya hai. Iska main kaam yeh hai ki jo students ne fee nahi bhari — unhe automatically track karo, email alerts bhejo, aur payment process karo. Pura system real-time hai aur multiple technologies ko ek saath integrate karta hai.

💡 Simple shabdon mein samjho:

Imagine karo ek college hai. Hazaron students hain. Fee collection manually track karna mushkil hai. Yeh system admin ko ek dashboard deta hai jahan se woh sab kuch dekh sakta hai — kaun defaulter hai, kitni fee baaki hai, payment kab ki thi — aur ek click mein sab defaulters ko email alert bhej sakta hai. Students apna portal khol ke online pay kar sakte hain ya bank challan upload kar sakte hain.

Section 04
Deployment — Kaha Deploy Hai?
☁️ Vercel — Frontend
  • Next.js 14 App Router deployed on Vercel
  • Automatic HTTPS + CDN globally
  • Every git push se automatic re-deploy
  • Environment variables: NEXT_PUBLIC_JAVA_API_URL, NEXT_PUBLIC_PYTHON_API_URL
  • Admin Dashboard + Student Portal dono yahan serve hote hain
🚀 Render — Backend
  • Java Spring Boot → Render Web Service (Dockerfile)
  • Python Flask → Render Web Service (Gunicorn/Waitress)
  • Dono Render pe free tier mein deployed hain
  • Auto-deploy on push to main branch
  • Keep-alive ping: har 14 min pe /health hit karta hai (cold start rokne ke liye)
🔁 n8n — Workflow Automation
  • n8n Cloud ya self-hosted pe run karta hai
  • 2 Webhooks listen karta hai: /fee-otp aur /payment-sheets
  • Email type ke hisaab se route karta hai
  • Google Sheets mein payments automatically log karta hai
  • Brevo API se email bhejta hai
🐘 Supabase — Database
  • PostgreSQL cloud database
  • Dono backends (Java + Python) same DB use karte hain
  • Connection via DATABASE_URL environment variable
  • Tables: student, fee, payment, offline_receipt, admin, fee_structure
  • Auto schema migration on startup

🔐 Admin Authentication — Security Features

Password Policy:

  • Minimum 6 characters
  • Pehla letter Capital hona chahiye (A-Z)
  • Ek special character zaroor (@, #, $, %)
  • Real-time checklist UI mein dikhta hai

Brute Force Protection:

  • Max 5 galat login attempts
  • 5 attempts baad 15-minute account lockout
  • User ko remaining attempts dikhta hai
  • Successful login pe counter reset

Section 06
Student Portal — Student Kya Kya Kar Sakta Hai?
🔑 OTP Login (Email Verification)

Student apna Roll No + Email deta hai. System OTP bhejta hai email pe (via n8n + Brevo). OTP verify karne ke baad student dashboard access milta hai. Koi password nahi — fully secure OTP-based authentication.

💳 Online Payment (Razorpay)

Student apni pending fee select karta hai. Razorpay payment window khulti hai. UPI, Credit/Debit Card, Net Banking support karta hai. Payment successful hone pe:

  • Fee record automatically update
  • Receipt ID generate
  • Payment success email student ko jaata hai
  • Google Sheets mein automatically entry
📄 Receipt Download

Student apna payment receipt PDF download kar sakta hai. Receipt mein student details, payment amount, transaction ID, date sab hota hai.

📸 Offline Challan Upload (AI OCR)

Jab student bank mein cash deposit karta hai:

  • Bank challan/receipt ki photo upload karo
  • Gemini AI image scan karta hai
  • UTR number, amount, date automatically extract hota hai
  • Admin ko pending challan dikhta hai
  • Admin approve/reject karta hai
  • Status email student ko jaata hai
🤖 EduAI — AI Chat Assistant

Student portal mein ek Gemini-powered AI chatbot hai — "EduAI". Student fee-related questions pooch sakta hai. Fee status, payment process, deadline — sab ke baare mein AI guidance deta hai.

# Gemini ko yeh prompt diya jaata hai:
"""
Analyze this bank transaction receipt/challan.
Extract the following information and return ONLY a valid JSON:
{
  "transaction_id": "12-16 digit UTR number",
  "amount": "numeric amount",
  "date": "DD/MM/YYYY format",
  "confidence": "High/Medium/Low"
}
"""

# Models tried in order (with retry logic):
GEMINI_MODELS = ['gemini-2.5-flash', 'gemini-1.5-flash', 'gemini-1.5-flash-8b']
# Automatic retry with exponential backoff (2s, 4s, 6s)
🔄 Smart Retry Logic:

Agar Gemini API busy/503 hai, system automatically dusre model pe switch karta hai. Max 3 retries per model. Total 3 models available hain — isliye almost kabhi fail nahi hota.

⏰ Cron Job (Automatic Scheduled Alerts)

APScheduler use karke 2 background jobs run karta hai:

  • Monthly Fee Reminder: Har mahine ke 1st din, subah 9 baje automatically sabhi defaulters aur partial payers ko email alert jaata hai
  • Keep-Alive Ping: Har 14 minute mein /health endpoint hit karta hai — Render free tier pe cold start rokne ke liye
# Monthly reminder — 1st of every month at 9 AM
scheduler.add_job(
  func=monthly_fee_reminder_job,
  trigger='cron',
  day='1', hour='9',
  args=[app]
)

# Keep-alive ping every 14 min
scheduler.add_job(
  func=self_ping_job,
  trigger='interval',
  minutes=14
)

Section 14
Complete Data Flow — Ek Payment Kaise Hoti Hai?
1 Student Vercel frontend pe /student-login pe jaata hai → Roll No + Email deta hai
2 Python Flask OTP generate karta hai → n8n webhook call karta hai (email_type: otp_verify)
3 n8n OTP email Brevo se bhejta hai → Student OTP dalta hai → Dashboard access milta hai
4 Student apni fee status dekhta hai → "Pay Now" click karta hai → Amount enter karta hai
5 Python Flask Razorpay Order create karta hai → Frontend pe Razorpay checkout window khulti hai
6 Student UPI/Card se pay karta hai → Razorpay payment ID milta hai
7 Python Flask Razorpay signature verify karta hai → Fee record update karta hai → Payment save karta hai
8 n8n webhook call hota hai → Brevo se "Payment Success" email jaata hai student ko
9 Google Sheets webhook call hota hai → 16 columns ke saath payment row automatically Google Sheets mein append ho jaata hai

✅ Poora flow automated hai! Admin ko kuch bhi manually karne ki zaroorat nahi — payment se email tak sab automatic hota hai.
